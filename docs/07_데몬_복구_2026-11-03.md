## 2. 원인 — `.cmd` 파일의 UTF-8 한글

cmd.exe 는 `.cmd` 를 **OEM 코어페이지(cp949)** 로 읽는다.
파일이 UTF-8 로 저장되어 있으면 한글 바이트가 깨지면서 **다음 줄까지 파싱이 무너진다.**

```bat
REM Trend Radar 자동 수집 데몬 시작 (로그온 시 실행)   ← 이 줄의 UTF-8 바이트가
start "" /min powershell.exe ...                         ← 다음 줄을 망가뜨림
```

실제 실행 결과:
```
'작' is not recognized as an internal or external command,
'n' is not recognized as an internal or external command,
```
→ `start "" /min` 의 **"min" 이 "n" 으로 잘려서** 명령이 조용히 실패.

**왜 아무도 몰랐나:** Startup 스크립트는 **한 번도 실제로 발화 검증된 적이 없었다.**
2026-10-24에 데몬을 *수동으로* 띄운 뒤 Startup 폴더에 파일을 "복사"만 했고,
"복사됨 = 동작함" 이라고 가정했다. 재부팅 전까지는 안 깨지는 게 정상이라 확인이 안 됐을 뿐.

## 3. 수정

### 3-1. 한글 경로 회피 — ASCII junction
프로젝트 경로에 한글이 있어 `.cmd` 에 그대로 쓰면 또 깨진다.

```
C:\Users\ue-agent\Documents\trend-radar      ← junction (ASCII)
  → C:\Users\ue-agent\Documents\기본 프로젝트\trend-radar
```
`mklink /J` 로 생성. 데몬은 `$PSScriptRoot` 기준이라 junction 경로로 호출해도
data/ logs/ 는 동일 위치에 쓰인다.

### 3-2. `.cmd` 는 순수 ASCII + CRLF + BOM 없음
`tools/fix_cmd_encoding.mjs` 가 이를 강제한다.

```powershell
$raw = $raw -replace "^\uFEFF", ''        # BOM 제거
$raw = $raw -replace "\r\n", "`n" -replace "`n", "`r`n"   # CRLF
$raw = $raw -replace '[^\x00-\x7F]', ''   # 비ASCII 제거
[IO.File]::WriteAllText($f, $raw, [Text.Encoding]::ASCII)
```

### 3-3. 런처가 스스로 로그를 남김
`%LOCALAPPDATA%\TrendRadar\startup.log` 에 발화 사실과 fatal 을 기록.
"안 돌아가는" 상태를 **조용히** 두지 않기 위함.

### 3-4. stale lock 제거 (2026-11-03 추가)
`data\.daemon.lock` 은 프로세스 크래시 시 남으면 **영영 수집이 안 돌던** 구조였다.
2시간 이상 지난 lock 은 stale 로 간주해 제거.

## 5. 앞으로 이걸 잊지 않기 위한 규칙

1. **`.cmd` 에 UTF-8 한글 금지.** 주석도 영어로. (프레임워크 메모리에도 있음)
2. **Startup 등록 = 실제로 발화까지 검증.** 등록만 하고 넘어가지 않는다.
   → `cmd /c "<startup 경로>"` 를 실제로 돌려서 로그가 찍히는지 확인.
3. **경로에 언어가 들어가면 ASCII junction 을 만든다.**
4. 데몬/스케줄러는 **"멈췄다"를 로그로 알린다.** 조용한 실패가 가장 비싸다.
